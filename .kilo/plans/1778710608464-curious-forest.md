# Fix Plan: gh-commit extension improvements

## Problem Description
The gh-commit GitHub CLI extension needs several improvements:
1. Remove debug logs that clutter output
2. Make y/n/e responses immediate (without requiring Enter key)
3. Ensure proper commit message generation from Kilo API
4. Fix input handling issues

## Current Code Analysis
From reviewing main.go:
1. Extension requires KILO_API_KEY environment variable
2. Stages all changes with `git add .`
3. Gets staged diff with `git diff --cached`
4. If diff empty, exits with "No staged changes to commit."
5. Calls Kilo API to generate commit message
6. On API failure, falls back to manual entry
7. Prompts user to accept/edit message
8. Commits with final message

## Current Issues
1. Debug logs throughout the code (prefixed with "DEBUG:") - STILL NEED TO REMOVE
2. Input requires pressing Enter after y/n/e selection - STILL NEED TO IMPLEMENT IMMEDIATE INPUT
3. stdin sometimes returns EOF when prompting for confirmation - PARTIALLY ADDRESSED
4. Need to ensure commit messages are properly extracted from API response (content vs reasoning fields) - ALREADY IMPLEMENTED

## Solution Approach
1. Remove all debug log statements
2. Implement immediate character input for y/n/e responses (without Enter)
3. Keep line-based input for multi-line commit message editing
4. Ensure proper handling of API response (check both content and reasoning fields) - ALREADY DONE
5. Maintain fallback to heuristic message generation on API failure - ALREADY DONE
6. Fix input reading to work reliably across platforms

## Specific Changes Needed
1. Remove all fmt.Println/fmt.Printf statements with "DEBUG:" prefix from main.go
2. Replace promptCommitConfirmation and related functions to use immediate character input
3. For single character input (y/n/e): implement raw terminal mode or equivalent
4. For multi-line input (edit message): keep using bufio.NewReader or similar
5. API response handling already checks both Content and Reasoning fields - VERIFY
6. Error handling for API responses already implemented - VERIFY

## Implementation Details
For immediate character input:
- Use terminal/term package to put terminal in raw mode temporarily
- Read single byte and return it as a character
- Restore original terminal state afterwards
- Handle errors gracefully by falling back to line-based input if needed
